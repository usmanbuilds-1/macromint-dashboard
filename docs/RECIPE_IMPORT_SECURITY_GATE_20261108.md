# Recipe import: URLs retired, local text import enabled

**Decision (November 8, 2026):** Recipe imports accept **pasted ingredient text only**.
The app must not fetch any user-supplied recipe URL, server-side or client-side.

## Functional behavior

- Users open Foods → Recipes → Paste ingredients.
- Enter one ingredient per line, e.g. `200 g lentils`, `1 tbsp oil`, `2 onions`.
- Parse locally with a maximum of 10,000 characters and 30 lines.
- Quantities explicitly written in grams/kilograms can prefill grams **only after selecting a matching food**. Volumes, cups, spoons and pieces do not get guessed into grams.
- User must choose a nutrition-database match (or deliberately skip the line) and review grams before saving.
- No images, accounts, addresses, websites, AI calls, or raw pasted text are sent to an importer. Only the user's final confirmed recipe is saved through existing authenticated recipe operations.
- A line beginning with a URL or containing markup is rejected with an explanation.

## Retiring the old URL functionality

- The URL input, network client, HTML/JSON-LD parser and URL-import tests are removed from the application source.
- A defensive `recipe-import` Edge Function stub responds **410 Gone** to every request and makes **zero external fetch calls**, even if old environment flags remain set.
- Migration `0018_recipe_import_budget.sql` is retained in history, because it may already have run on some databases. Migration `0019_retire_recipe_url_import.sql` drops its now-unused function and quota table. No diary, recipe or saved-meal data are touched.
- On production, deploy the 410 Edge stub or remove the deployed `recipe-import` function; simply deleting client UI does not disable an older deployed function. Remove obsolete `RECIPE_IMPORT_*` and `VITE_RECIPE_URL_IMPORT_ENABLED` environment variables after verifying the deployment.
- Confirm that old direct function URLs return 410 (or 404 after deletion), never 200 with fetched content.

## Testing checklist

- Input validation: blank, 31+ ingredients, invalid links/markup, long lines, number formats and explicit g/kg limits.
- User journey: paste text → see original lines → match or skip each → edit grams → save → log and reuse.
- Honest nutrition: missing macros remain unknown; no calories generated by parsing ingredient text.
- Browser audit: 320px layout; the textarea does not autofocus or obstruct existing food search; no extra Today bundle or network call.
- Security: authentication and account ownership on final recipe saving; no SQL migrations required for local text parsing. The quota-removal migration is optional cleanup, not a prerequisite to the new text flow.

**Production deployment is a separate step:** GitHub merging doesn't update live Edge Functions or prove any SQL migration ran.
