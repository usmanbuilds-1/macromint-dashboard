# Separate restricted account access from paid feature entitlement

The owner approved on 2026-11-05 that expired or owner-revoked Macro Mint accounts must be signed out of the product on all devices, but may reauthenticate into a **restricted account-only area** to export or delete their own data. Expired testers may also request reactivation in an owner-only Admin queue. This is not a new trial and does not allow logging meals, editing tracking history or scanning food. When access is later restored, the existing identity and password work without any new invitation.

This separation is intentional: a single `has_access()` entitlement check on every account operation is simple but strands users who need privacy controls after expiry. Granting every authenticated account broad read privileges would instead weaken the private-beta paywall. The implementation must maintain server-side premium feature denial while offering only narrowly scoped account-management/data-subject operations, with rigorous cross-account isolation and complete **only-on-request** exports. Exporting must require an explicit authenticated user action; no automatic file generation, email delivery or sharing. UI sign-out on expiry/revocation and authentication into this restricted area are different transitions.

**Status:** accepted architectural rule; implementation and real-account RLS/export tests outstanding. Revoked users' export and deletion rights are approved; whether they may submit reactivation requests is not yet decided.
